### JJS Moveset Creation Guidelines
- Set `LastHit` to `0.01` immediately after the corresponding Hitbox node fires. This prevents lingering hit registration from affecting unrelated attacks.
- visuals attached to limbs must be positioned else they will have the Coordinate frames of the limb
- Visual positioning uses `Limb.CFrame * YourPositionSettings`, applying offsets relative to the selected limb's CFrame. This does not however affect these visual effects: afterimage, afterimage 2, glow and meele trail.
- Account for the typical 1–1.5 stud downward offset from the default limb spawn position when positioning fist visuals. Cursed energy and rough energy effects are exempt from this along with afterimages, glow and meele trails.
- Visual offsets for individual animations are unnecessary when effects are attached to limbs, since they follow the limb's CFrame. Manual animation-specific positioning is relevant when attaching effects to the HumanoidRootPart.
- Preserve the website's exact JSON structure, node identifiers, property names and import encoding format.
- Always compare generated moveset JSON against the website's template before providing import codes.
### JJS Animation Splicing Guidelines
- Splice useful middle/action sections of animations rather than unnecessary neutral poses, windups or recovery frames.
- Choose compatible poses between animation segments to prevent unnatural snapping.
- `Fade In` determines how long an animation takes to interpolate, not how long it waits before starting.
- Fade In/Out is optional and should only be used when it improves the transition.
- **Known bug:** Fade In/Out does not work between spliced sections of the same animation. Use hard cuts instead.
- When blending different animations, ensure sufficient overlap for interpolation to complete.
- Synchronize hitboxes and visual effects with the actual attack frames after splicing.
- Prioritize smooth, natural-looking attacks over excessive interpolation or animation segments.
### JJS Import Code Compatibility Guidelines
- JJS imports use Base64-encoded Zstandard-compressed JSON.
- Match the compression format of a known working JJS export.
- **Confirmed working format:** Zstandard frame descriptor `0x60`, with uncompressed content size included and checksum disabled.
- **Known issue:** Codes using frame descriptor `0x04` failed despite successfully decoding and decompressing.
- Valid JSON and successful decompression do not guarantee a working import.
- Test a simple skill before importing complex movesets or awakenings.
- Use `AWK` for base skills and `AWK2` for awakening skills.
- If imports fail, check compression and node structures before blaming awakening logic.
- **Note:** Other changes were made in the successful version, so compression was not confirmed as the sole cause.
### JJS Awakening Moveset Guidelines
- Awakening movesets require an `AWAKENING` block with valid `DATA` and `DURATION` properties.
- Use `AWK: true` for base skills and `AWK2: true` for awakening-only skills.
- Awakening skills should replace their corresponding base skills when awakening activates.
- Keep base and awakening skills in separate skill blocks with valid node structures.
- Awakening animations, particles, buffs, and effects can be added to the awakening timeline.
- Set `DURATION` to control how long the awakening lasts.
- Ensure awakening skills and effects use supported properties and valid timing.
- **Important:** A failed awakening import does not necessarily mean the awakening structure is incorrect; check encoding and compression too.
